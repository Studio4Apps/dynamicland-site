# Security and discovery handoff

Verified against official documentation on 2026-09-22. This describes the actual read-only marketing site and the remaining host/account work; it is not a penetration-test certification.

## Threat model and controls

| Surface / threat                          | Implemented                                                                                                                                                                                                                                                                                                 | Owner / hosting responsibility                                                                                                                                                                                                    |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Untrusted content / XSS                   | React escaping; no user content, uploads, forms, actions or URL-derived HTML. JSON-LD alone uses a tested serializer escaping `<` and Unicode separators. HTTP-injected unnonced script test proves browser enforcement.                                                                                    | Review future content integrations before adding them.                                                                                                                                                                            |
| Script loading / clickjacking             | Enforced response CSP, random 24-byte per-response nonce, `strict-dynamic`; no production script `unsafe-inline`/`unsafe-eval`; object/base/form/frame denial. External script/widget sources absent.                                                                                                       | Preserve headers at CDN/proxy; retest the actual host. CSP limits impact but does not fix a compromised trusted bundle.                                                                                                           |
| HTML caching                              | Request nonce is overwritten server-side, passed to Next through CSP/x-nonce, and matched in markup. Dynamic HTML with `private, no-store`. Full-document route navigation.                                                                                                                                 | Never cache/replay nonce HTML across requests. Static hashed chunks may be cached separately.                                                                                                                                     |
| Styles / media                            | CSS Modules; `style-src` self + nonce. Narrow `style-src-attr 'unsafe-inline'` supports typed CSS custom properties and Next visibility attributes. WAAPI handles finite motion; script policy stays strict. Raster owner logo; local validated future media; image optimization disabled, no remote proxy. | Review new source sets, captions, crop and file metadata.                                                                                                                                                                         |
| Dependency / build supply chain           | Exact manifest/lockfile, Node/pnpm versions, locked install, explicit dependency build-script allowance, full dependency audit. SHA-pinned GitHub Actions, read-only job token, no saved checkout credentials.                                                                                              | Enable branch protection, Dependabot/security alerts and repository secret scanning/push protection if available. Review updates promptly. CI definition is prepared, not remotely executed.                                      |
| Accidental private output                 | Private references stay outside source imports/public. Scanner checks authored execution/sensitive patterns and public/browser output paths/types; route probes confirm docs/.env/.git/artifacts are not served. No browser source maps.                                                                    | Deploy the Next runtime and approved public assets, never expose the repository root as a static directory. The bounded pattern scan is not an exhaustive secrets audit.                                                          |
| Preview exposure                          | Explicit local/preview mode, HTML meta noindex, X-Robots-Tag, empty sitemap. No assumed canonical hostname.                                                                                                                                                                                                 | Add hosting access protection. Robots/noindex are indexing signals, never authentication; static brand files are public if the host is public.                                                                                    |
| Network / account takeover / availability | Same-origin resources, no API keys or credentials, no sessions or state-changing endpoints. Nosniff, DENY frame header, strict-origin referrer policy, restricted browser permissions.                                                                                                                      | HTTPS, certificate rotation, HSTS after verifying owned domains, rate limiting, least-privilege deployment access/MFA, backups and incident response. No preload/includeSubDomains or cross-origin isolation added speculatively. |

Local development alone permits the framework's evaluation/style/HMR connections. Production-mode tests assert these allowances do not leak into the script policy. Framework strategy follows [Next CSP documentation](https://nextjs.org/docs/app/guides/content-security-policy); policy choices follow [OWASP CSP](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html) and [HTTP headers](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html). Installed Next guides were read before implementation. The installed 16.3.5 release was checked against [Next security advisories](https://github.com/vercel/next.js/security/advisories), including the [August security release](https://nextjs.org/blog/august-2026-security-release).

No CSRF/session machinery is needed for the current site: it has no authenticated state-changing functionality. App Store, owner Notion policies and mailto support are explicit user-selected destinations. The website itself does not contact those services in the background.

## Search and AI retrieval policy

Core copy is server-rendered and useful without JavaScript. Semantic headings, real links, unique page metadata, icon, original logo/text social card, and shared facts for JSON-LD/llms.txt are implemented. Production canonicals and stable website IDs derive only from configured `SITE_ORIGIN`, never request headers. A Person publisher and SoftwareApplication are present; WebSite/absolute images become available when the real origin is configured. Without one, the official App Store identity is the temporary app ID base, and no localhost canonical is emitted.

No prices, offers, fabricated ratings or reviews are in JSON-LD. This is truthful Schema.org description, not a claim of eligibility for Google's software-app rich results; those have additional [required properties](https://developers.google.com/search/docs/appearance/structured-data/software-app). No last-modified dates are invented. `llms.txt` is a short factual supplement with the official download and configured canonical links, not a ranking instruction or a substitute for accessible HTML.

The shared robots group allows `/`, including on previews so crawlers can read noindex. Specific blocked groups contain a complete `Disallow: /`; discovery agents use the shared group and do not accidentally inherit a training restriction. The separate `TRAINING_CRAWLERS` setting defaults to `block` for GPTBot, ClaudeBot, Google-Extended, Applebot-Extended and CCBot. Some providers' generative-use controls cover more than training, as described below. Permitting training does not promise better search ranking.

| Agent / token                              | Role and policy rationale                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Googlebot                                  | Search crawling; accessible shared group. Google Search AI features use the ordinary search controls and do not require special AI markup. Google-Extended separately controls certain Gemini training and grounding uses, and does not control Search inclusion. [Google AI guidance](https://developers.google.com/search/docs/appearance/ai-features), [crawler tokens](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers). |
| bingbot                                    | Bing discovery; shared group. Specific groups override general rules, so do not casually add conflicting bot-only sections. Verify crawler identity through supported IP/DNS mechanisms. [Bing robots](https://www.bing.com/webmasters/help/how-to-create-a-robots-txt-file-cb7c31ec), [verification](https://www.bing.com/webmasters/help/how-to-verify-bingbot-3905dc26).                                                                                       |
| OAI-SearchBot / ChatGPT-User / GPTBot      | Search indexing, user-requested fetches and model-development crawling are distinct. Search remains accessible; GPTBot blocked by default. User-initiated retrieval may not obey robots in the same way as automatic crawlers. [OpenAI crawler documentation](https://developers.openai.com/api/docs/bots).                                                                                                                                                       |
| Claude-SearchBot / Claude-User / ClaudeBot | Search, user retrieval and model training have separate tokens. Search/user access is allowed, training blocked by default. [Anthropic crawler documentation](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).                                                                                                                                                                   |
| PerplexityBot / Perplexity-User            | Search discovery and user-requested retrieval, respectively. Neither is presented as a foundation-model training requirement. User fetches generally do not follow robots as an automatic crawler would. [Perplexity documentation](https://docs.perplexity.ai/docs/resources/perplexity-crawlers).                                                                                                                                                               |
| Applebot / Applebot-Extended               | Apple search discovery versus separate generative-model usage opt-out. Ordinary Applebot remains allowed. [Apple documentation](https://support.apple.com/en-us/119829).                                                                                                                                                                                                                                                                                          |

There are **no** User-Agent-based WAF bypasses in the app. Simulated UA requests tested response consistency only. If a future CDN challenges legitimate search, use its verified-bot integration or the provider's documented verification, retaining rate limits. Do not trust an easily forged UA or disable protections globally.

## Owner-controlled launch sequence

1. Choose the canonical HTTPS domain. Supply and approve website privacy/terms text covering the actual hosting/logging practices. Replace pending notices, set the explicit readiness flag and `LEGAL_APPROVED=true`; use `SITE_ENV=production` and the correct `SITE_ORIGIN` for both build and runtime. Run the release check; intentionally deferred product media is allowed.
2. With deployment authorization, configure the Next Node runtime behind HTTPS. Keep preview access protection/noindex and production settings separate. Verify redirects, all routes/404, headers, fresh nonces, cache behavior, canonical URLs, JSON-LD, sitemap, robots, social image and download link on the actual host.
3. Verify the domain in Google Search Console (owner-added DNS TXT or approved verification method), submit `/sitemap.xml`, and inspect the homepage. Verify/import the site in Bing Webmaster Tools and submit the same sitemap. No account verification or submission has been performed here.
4. IndexNow is optional for later content-change notifications to participating engines; this four-page site does not justify a new backend or credential merely for it. Add owner-controlled key verification and a deployment hook only if frequent meaningful changes warrant it. It is not Google submission and is not a ranking guarantee. Follow [IndexNow's protocol](https://www.indexnow.org/documentation).
5. After launch, review crawl errors, indexing/canonical reports, real query impressions, referral accuracy and app descriptions. Re-check compatibility/Pro boundaries against released App Store updates. Real reviews and reputation require ongoing owner work. Field Core Web Vitals and final-media performance remain unmeasured.
